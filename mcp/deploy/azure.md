# Deploying to Azure Container Apps with Azure SQL Database

End to end, from an empty resource group to a tool the world can call.
Placeholders in `<angle brackets>` are yours to fill.

> ⚠️ **Public ingress is required.** The frontier-tuning runtime calls this
> endpoint from the Microsoft 365 substrate, not from your network. A private
> endpoint, VNet-only ingress or an IP allow-list scoped to your office produces
> a tool that registers successfully and then silently returns nothing — which
> looks exactly like a retrieval failure and will cost you a day.

---

## 0. Variables

```bash
RG=rg-frontier-tuning-showcase
LOC=centralindia
ACR=acrcontososervice$RANDOM
APP=contoso-service-mcp
ENVNAME=cae-frontier-tuning
SQLSRV=sql-contoso-service-$RANDOM
SQLDB=contoso
SQLADMIN=ctadmin
SQLPASS='<a-strong-password>'
```

## 1. Resource group and registry

```bash
az group create -n $RG -l $LOC
az acr create -g $RG -n $ACR --sku Basic --admin-enabled true
```

## 2. Azure SQL Database

Serverless General Purpose with auto-pause is the right shape for a
demonstration corpus of ~3,300 rows.

```bash
az sql server create \
  -g $RG -n $SQLSRV -l $LOC \
  --admin-user $SQLADMIN --admin-password "$SQLPASS"

az sql db create \
  -g $RG -s $SQLSRV -n $SQLDB \
  --edition GeneralPurpose --compute-model Serverless \
  --family Gen5 --capacity 1 \
  --auto-pause-delay 60 \
  --backup-storage-redundancy Local
```

Allow Azure services through the server firewall — this is what lets the
Container App connect:

```bash
az sql server firewall-rule create \
  -g $RG -s $SQLSRV -n AllowAzureServices \
  --start-ip-address 0.0.0.0 --end-ip-address 0.0.0.0
```

Add your own address so you can load the seed:

```bash
MYIP=$(curl -s ifconfig.me)
az sql server firewall-rule create \
  -g $RG -s $SQLSRV -n AllowMyIP \
  --start-ip-address $MYIP --end-ip-address $MYIP
```

⚠️ **Auto-pause and cold starts.** At `--auto-pause-delay 60` the database
suspends after an hour idle and takes ~30–60 seconds to resume. The first tool
call of a demonstration will time out. Either warm it with a `/healthz` request
a few minutes beforehand, or set `--auto-pause-delay -1` to disable pausing on
the day.

### Load the schema and seed

```bash
sqlcmd -S $SQLSRV.database.windows.net -d $SQLDB \
       -U $SQLADMIN -P "$SQLPASS" -C \
       -i ../../out/db/seed.azuresql.sql
```

`seed.azuresql.sql` is generated by `scenario/build/gen_db.py` in T-SQL, with
`GO` batch separators every 500 statements. Regenerate it rather than editing
it — the SQLite and Azure SQL scripts come from one templated schema, so they
cannot drift apart.

Confirm the load, and that the trap is armed:

```bash
sqlcmd -S $SQLSRV.database.windows.net -d $SQLDB -U $SQLADMIN -P "$SQLPASS" -C \
  -Q "SELECT COUNT(*) AS assets FROM Assets;
      SELECT tsb_id, serial_to FROM TsbApplicability WHERE tsb_id='TSB-C-0051';"
```

Expect **117 assets**, and `TSB-C-0051` with `serial_to = 1500`. The bulletin
document says 1850. That difference is trap 1 and it is meant to be there.

## 3. Build and push the image

```bash
cd scenario/mcp
az acr build -r $ACR -t $APP:v1 .
```

The image installs **ODBC Driver 18 for SQL Server**. Without it `pyodbc` fails
to import at runtime with an unhelpful "can't open lib" message.

## 4. Container App

```bash
az containerapp env create -g $RG -n $ENVNAME -l $LOC

ODBC="Driver={ODBC Driver 18 for SQL Server};Server=tcp:$SQLSRV.database.windows.net,1433;Database=$SQLDB;Uid=$SQLADMIN;Pwd=$SQLPASS;Encrypt=yes;TrustServerCertificate=no;Connection Timeout=60;"

az containerapp create \
  -g $RG -n $APP \
  --environment $ENVNAME \
  --image $ACR.azurecr.io/$APP:v1 \
  --registry-server $ACR.azurecr.io \
  --target-port 8000 \
  --ingress external \
  --min-replicas 1 --max-replicas 3 \
  --cpu 0.5 --memory 1.0Gi \
  --secrets "odbc=$ODBC" \
  --env-vars "AZURE_SQL_CONNECTION_STRING=secretref:odbc"
```

`--min-replicas 1` matters. Scale-to-zero means the first tool call of a session
pays a cold start on top of the database resume, and an agent that times out
looks like a broken world.

`Connection Timeout=60` gives the serverless database room to wake up.

Check it:

```bash
FQDN=$(az containerapp show -g $RG -n $APP \
        --query properties.configuration.ingress.fqdn -o tsv)
curl -fsS https://$FQDN/healthz
# {"status":"ok","assets":117}
```

### Preferred: managed identity instead of a password

```bash
az containerapp identity assign -g $RG -n $APP --system-assigned
PRINCIPAL=$(az containerapp show -g $RG -n $APP \
             --query identity.principalId -o tsv)
```

Then, connected to the database as an Entra admin:

```sql
CREATE USER [contoso-service-mcp] FROM EXTERNAL PROVIDER;
ALTER ROLE db_datareader ADD MEMBER [contoso-service-mcp];
ALTER ROLE db_datawriter ADD MEMBER [contoso-service-mcp];
```

Switch the app over — note the connection string now carries no `Uid`/`Pwd`:

```bash
ODBC_MI="Driver={ODBC Driver 18 for SQL Server};Server=tcp:$SQLSRV.database.windows.net,1433;Database=$SQLDB;Encrypt=yes;TrustServerCertificate=no;Connection Timeout=60;"

az containerapp update -g $RG -n $APP \
  --set-env-vars "AZURE_SQL_CONNECTION_STRING=$ODBC_MI" \
                 "AZURE_SQL_USE_MANAGED_IDENTITY=true"
```

`db.py` then fetches an Entra token via `DefaultAzureCredential` and passes it to
the driver as `SQL_COPT_SS_ACCESS_TOKEN`. No password exists to leak.

`db_datawriter` is needed because the three action tools write draft rows. They
write nothing else — no updates to claims beyond setting a held status, and no
deletes.

## 5. Entra app registration for the MCP endpoint

This is separate from the database identity above: it is how the
frontier-tuning runtime authenticates **to this server**.

```bash
APPID=$(az ad app create --display-name "Contoso Service MCP" --query appId -o tsv)
az ad app update --id $APPID --identifier-uris "api://$APPID"
TENANT=$(az account show --query tenantId -o tsv)
echo "audience: api://$APPID"
echo "tenant:   $TENANT"
```

Turn validation on:

```bash
az containerapp update -g $RG -n $APP \
  --set-env-vars "ENTRA_TENANT_ID=$TENANT" "API_AUDIENCE=api://$APPID"
```

> Until both are set, `auth.py` skips validation — which is what makes local
> development work. Do not leave it that way in a tenant anyone else can reach.

## 6. Register the tool with the world

```powershell
frontier-tuning tools create `
  --name contoso-service `
  --description "Contoso service claim system: asset registry, running-hours telemetry, service history, claims, partner master, parts, goodwill authority, and draft adjudication actions." `
  --url https://<fqdn>/mcp `
  --auth-scheme AzureAD `
  --aud api://<app-id> `
  --env-id $envId

frontier-tuning tools sources --env-id $envId      # the stable server id
frontier-tuning tools enable <server-id> --env-id $envId
frontier-tuning tools available --env-id $envId -o json | Select-String contoso
```

`tools list` shows callable actions; `tools sources` shows the server id that
`enable` / `disable` accept. They are not the same identifier.

## Staging the demonstration

The hill climb needs this server **registered but switched off** at stage 0, so
the naive build fails for a diagnosable reason:

```powershell
frontier-tuning tools disable <server-id> --env-id $envId   # stage 0
frontier-tuning tools enable  <server-id> --env-id $envId   # stage 1
```

Reversible, instant, and it changes nothing about the corpus — which is what
keeps the stage-0 and stage-1 scores comparable.

## Cost

Indicative list price for a demonstration environment:

| Resource | Sizing | Monthly |
| --- | --- | --- |
| Azure SQL serverless | GP_S_Gen5_1, auto-pause after 1 h | ~$5–15 depending on active hours |
| Container Apps | 0.5 vCPU / 1 GiB, 1 replica always on | ~$15–25 |
| Container Registry | Basic | ~$5 |

Auto-pause does most of the saving. Scale the Container App to zero between
sessions if it is only used for scheduled demonstrations — but remember to warm
both before a demo.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| `Can't open lib 'ODBC Driver 18 for SQL Server'` | Image built without `msodbcsql18`. Rebuild from the provided Dockerfile |
| `/healthz` returns 503 after idle | Serverless database resuming. Retry after 60 s, or disable auto-pause |
| `Login failed for user '<token-identified principal>'` | Managed identity assigned but no database user created — see step 4 |
| Tool registers but every call returns empty | Ingress is not publicly reachable from the substrate |
| `Cannot open server ... not allowed to access` | Firewall rule for Azure services missing |
| Dates come back as objects, not strings | Running an adapter other than `_MssqlAdapter`. Normalisation lives there |
